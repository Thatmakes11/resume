\section{Loops}
\resumeentry
    {Agent Loop｜提升 Agent 能力}
    {我更关注 Agent 如何从“偶尔做对”走向“稳定完成任务”}
\begin{itemize}
    \item \textbf{Harness 是随模型能力变化的脚手架：}
    当模型能力尚未覆盖业务时，对 Harness 做加法，把人对业务的理解编码为 State、Tool、Skill、Rule、Eval 与 Review Gate；当模型迭代、能力升级时，对 Harness 做减法，移除不再必要的流程和约束，在保留可观测性与安全边界的同时释放模型能力。
    \item Coding Agent 与 Business Agent 应保持边界：前者对实现、测试和 Artifact 负责，后者对语境、规则与验收负责。好的协作不是让一个 Agent 知道一切，而是让不同责任可以被检查。
\end{itemize}

\resumeentry
    {My Loop｜提升自身能力}
    {AI 提高了答案的供给，而人的优势更集中在问题、判断、体验与责任}
\begin{itemize}
    \item \textbf{提出值得回答的问题：}
    当生成答案越来越便宜，真正稀缺的是发现什么值得做、为谁做，以及什么约束不能被忽略。我希望自己持续深入真实场景，而不是只在已有问题上优化答案。
    \item \textbf{形成 Taste 与承担判断：}
    Agent 可以扩展候选空间，但无法替我承担取舍的后果。我的价值在于结合上下文、长期目标与审美，判断什么是“技术上可行但不值得”，什么是“不完美但方向正确”。
    \item \textbf{保留人的感知与体验：}
    Humans Are Visual Animals。观察、同理心和对现实细节的感受，是我理解用户与问题的 Grounding；Diagram 与 Prototype 则帮助我把直觉外化，与 Agent 和他人共同检验。
    \item \textbf{用 Agent 放大而非替代思考：}
    我愿意把检索、实现和验证中的重复劳动交给 Agent，把时间留给问题建模、关键实验和复盘；最终目标不是更依赖 Agent，而是借助每次协作形成更好的判断与方法。
\end{itemize}
